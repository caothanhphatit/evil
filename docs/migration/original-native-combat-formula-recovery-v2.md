# Original Native Combat Formula Recovery v2

## Scope

This recovery pass reads bounded native code bytes from the authorized Android
API 35 runtime. It does not read player values, account state, or original
service credentials. The exact-boundary capture is
`reverse-engineering/evidence/original-native-combat-formula-exact-boundaries-api35-v1.json`.
Its deterministic normalized analysis is
`reverse-engineering/evidence/original-native-combat-formula-analysis-v1.json`,
generated by:

```sh
python3 tools/analyze-il2cpp-native-combat.py
python3 -m unittest tools.tests.test_analyze_il2cpp_native_combat
```

## Captured native boundaries

The live IL2CPP reflection boundary resolved sixteen formula-relevant methods:

- `HunterCtrl`: `getDamage`, `getCriticalDamage`, `HitDamageProcess`,
  `HuntingAttackSetting`, `FireDamageAction`, and `Damaged`.
- `EvilCtrl`: `Damaged`, `ForcedDamaged`, `FireDamage`, and
  `GetReduceAttackValue`.
- `GameManager`: `GetGearDamage`, `GetGearArmor`, `GetGearAcc`,
  `GetSealAttackUp`, `GetCostumeAttackUp`, and `GetCostumeArmorUp`.

The capture preserves method tokens, parameter and return types, live
`libil2cpp.so` module offsets, the next unique Assembly-CSharp method pointer,
and exact native boundary sizes. Fifteen bodies are complete. The exact
`HunterCtrl.Damaged` boundary is 18,964 bytes, but its captured code is limited
to the first 16,384 bytes; the analyzer records this distinction instead of
claiming a complete-body hash.

A subsequent dedicated capture stores the complete 18,964-byte body at
`reverse-engineering/evidence/original-native-hunter-damage-intake-api35-v1.json`.
The original sixteen-method analyzer remains pinned to its earlier bounded
input, while damage-intake conclusions use the complete dedicated capture.

For every method, the analyzer emits an exact-boundary descriptor hash,
captured-code hash, direct `BL` targets normalized to module offsets, resolved
calls among the sixteen captured methods, direct `x0` field offsets, scalar
float immediates, and deterministic float-arithmetic signatures. A complete
body hash is emitted only when the captured body is not truncated.

## Newly recovered formula increment

`EvilCtrl.GetReduceAttackValue()` has a complete 88-byte ARM64 body ending in a
single `ret`. Before constructing the returned `ObscuredFloat`, it reads three
`System.Single` fields at `EvilCtrl` offsets `0x1E4`, `0x1EC`, and `0x1F4` and
computes:

```text
(1 - value_0x1E4) * (1 - value_0x1EC) * (1 - value_0x1F4)
```

The arithmetic and multiplicative stacking order are native-confirmed. The
three fields remain obfuscated as `PHKJDKANJOA`, `DBGLOFBIEBL`, and
`BOKEIJGPICA`; their gameplay source labels must be resolved from writers and
callers before the formula is connected to the authoritative Rust runtime.

`GameManager.GetCostumeAttackUp(Int32)` currently resolves to a native body
that returns `0.0`. This is exact for package `1.411`, but the caller must still
be audited before removing or folding any surrounding modifier branch.

`GameManager.GetCostumeArmorUp(Int32)` has the same exact eight-byte native body
and also returns `0.0`. Both bodies have SHA-256
`eb2f99aeafe6fa666d90e46dfe69f2cae11e2bf912999b07d3d262a152ad072c`.

`HunterCtrl.getCriticalDamage()` contains the scalar float immediate `1.75` at
native instruction offsets `164` and `252`. This confirms the base constant in
the captured package, but not the meaning or order of every modifier applied by
the rest of the 1,908-byte body.

## Still unresolved

- `HunterCtrl.getDamage` has a large modifier call graph; its base damage,
  armor, critical, dodge, skill and rounding order are not yet normalized.
- `HunterCtrl.getCriticalDamage` contains the native `1.75` multiplier and
  accumulates several runtime modifiers, but the referenced object fields and
  helper calls are not yet completely named.
- `GameManager.GetGearDamage`, `GetGearArmor`, and `GetGearAcc` require exact
  method boundaries plus `GearData` field/callee resolution before translation.
- Attack cadence still requires recovery of the `HuntingAttackSetting` caller
  chain and the fields that convert Hunter attack-speed state into wait time.
- Monster damage intake, critical/miss behavior, EXP/gold modifiers and the
  complete unique-drop modifier chain remain pending.

## Implementation policy

No newly captured formula is connected to gameplay until its inputs have
semantic names and deterministic golden vectors. Each accepted formula must be
implemented in the Rust authoritative layer, not trusted from browser output.
