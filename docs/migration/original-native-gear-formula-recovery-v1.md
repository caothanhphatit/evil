# Original Native Gear Formula Recovery v1

## Recovered boundaries

Pass 2 normalizes the exact package `1.411` bodies for `GetGearDamage` (1,272
bytes), `GetGearArmor` and `GetGearAcc` (1,124 bytes each), and
`GetSealAttackUp` (492 bytes). A separate authorized pointer/body capture
confirmed `GetWeaponCostumeAttackUp` at module offset `0x271fd38`, 296 bytes,
SHA-256 `bcc55d3a563208f7d2011d43abc2f43d9602a41971266b2d40071cd535f53839`.

The deterministic record is generated by:

```sh
python3 tools/analyze-il2cpp-native-gear-formulas.py
python3 -m unittest tools.tests.test_analyze_il2cpp_native_gear_formulas
```

## GearData inputs

All three Gear methods preserve the `GearData` argument from `x1` in `x20` and
read the confirmed backing fields `index` (16), `gearIndex` (32), `quality`
(64), `level` (92), and `rating` (108). No evidence in these bodies proves that
`plusType`, `minusType`, runes, or their values participate directly.

`GetGearArmor` and `GetGearAcc` share the same control-flow shape:

```text
roundToEven(base * ratingPercent/100 * (1 + levelPercent/100) * qualityMultiplier)
```

The native quality multiplier is `0 -> 0.8`, `1 -> 0.9`, `3 -> 1.1`, `4 ->
1.2`, otherwise `1.0`. Rounding is nearest integer with midpoint ties to even.
The admin catalog base field, rating-table row, and level helper have not yet
been assigned semantic source names, so the expression uses neutral inputs.

`GetGearDamage` uses the same five GearData fields, `0.01`, the same quality
multipliers, and the same rounding routine. Its additional helper at module
offset `0x26bdf7c` and admin-row operands are unresolved, so publishing a full
damage expression would be speculation.

## Costume helpers

`GetSealAttackUp` accepts IDs `157..161`, `202`, `255`, `320`, `359`, `476`,
`489`, `531`, `706`, `758`, and `822`. Accepted rows return their first nested
integer multiplied by `0.01`; other IDs return `0.0`.

`GetWeaponCostumeAttackUp` performs vectorized range selection, then returns the
first nested integer multiplied by `0.01`, or `0.0` when rejected. Its range
constants are preserved in the evidence JSON. One SIMD lane clears an input bit
before comparison, so the final expanded ID list remains unresolved and must
not be guessed.

## Blockers

- Option type meanings and plus/minus/rune participation are not resolved.
- Helper `0x26bdf7c` has no proven managed name or formula.
- Admin row fields supplying base damage, armor, and accuracy lack serialized
  semantic bindings.
- Weapon-costume selector lanes need deterministic emulation before publishing
  an accepted ID catalog.

No formula in this report is connected to Rust simulation or UI.
